# Theory of Mind stakeholder map template

Use the map to see who matters to a role or project, how the work connects to them, and where to read more. Use the [stakeholder profile template](stakeholder-profile-template.md) to record and revise an evidence-backed understanding of a key person. Link the profiles and original records at their maintained private homes.

In the private work repository, open the map from the README’s **Theory of Mind** row. Use an existing map if it has a maintained home. Otherwise copy the structure below into `STAKEHOLDERS.md` and link it from the README. Also give the README direct links to the profiles people need most.

## Copyable map

```markdown
# Stakeholder map

<Link to the work-repo README and relevant project directory. State which work and relationships this map covers.>

| Person and role | How our work connects | Profile or existing record |
| --- | --- | --- |
| <Name and role> | <Work, decisions or handoffs that connect us> | <Direct link to the profile or evidence. Mark a pending profile as pending.> |

## Sources for profile reviews

<Link the existing source inventory or list each channel here. Give the starting route, what evidence it holds and known access limits. Record actual coverage and gaps in each profile.>

## Profile template and reading

<Link the OODA Theory of Mind explanation, the shared map and profile templates, and applicable reading. Keep private resources at their authorised home.>
```

Give a short profile a named heading on the map when its evidence and decisions make sense in this project. Give a profile its own linked page when several projects retrieve it, its evidence changes independently, or its access differs. Link that page back to the relevant map. Put **Profile template and reading** at the bottom of the map in either form. The [work-repo README convention](../roles/ROLE-TEMPLATE.md#work-repository-readme) shows how to surface these routes during role assembly.

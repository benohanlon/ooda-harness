# Visual communication

Use this reference when writing or reviewing schematic labels, explanations and technical diagrams. Read it with the current design brief.

**Primary reference:** [IBM Design Language — Technical diagrams](https://www.ibm.com/design/language/infographics/technical-diagrams/design/). Use it when drawing technical systems, harnesses and workflows. Its [layout guidance](https://www.ibm.com/design/language/layout/tips-and-techniques/) supports composition and visual hierarchy.

Apply its discipline for spacing, typography, node consistency and connector routing. Preserve the system's actual relationships and the selected brand kit. This is an IBM-informed adaptation, not a claim of IBM, ISO or WCAG conformance. For the harness schematic, Boyd's OODA relationships remain the foundation.

**Supporting references, selected by need:**

- [C4 notation](https://c4model.com/diagrams/notation) and [review checklist](https://c4model.com/diagrams/checklist): component types, scope, relationship meaning and legends.
- [TfL line-diagram standard](https://content.tfl.gov.uk/tfl-line-diagram-standard.pdf): consistent routing, spacing and labels. Do not copy transport symbols with different meanings.
- [WCAG text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast) and [use of colour](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): accessible distinctions.
- [ISO 5807](https://www.iso.org/standard/11955.html): flowchart notation. [ISO/IEC/IEEE 42010](https://www.iso.org/standard/74393.html): architecture-description requirements. Neither prescribes creative quality.

Set the intended viewing size and reading hierarchy before drawing. Distinguish component types and connection meanings. Keep essential text readable at that size; move supporting explanation to linked detail. Check the rendered artifact and ask a fresh reader to trace a real use. Passing label-fit checks alone does not establish good design.

Resolve the canonical design brief, brand kit, examples and acceptance tests from the assigned role, current task or private setup. Retrieve the relevant material and use its production workflow. Name any missing source and limit the assessment accordingly; generic design references do not replace the project’s acceptance tests. Keep historical candidates in their existing working record. These editorial references do not constitute a complete visual production method.
